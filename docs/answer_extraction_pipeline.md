# CHisEval VIP 试题答案与逐项推导解析自动化提取工作流

本文档详细说明高中历史评测基准 **CHisEval V0.1** 中针对付费 VIP 试题（组卷网/学科网）的解密、抓取、离线 OCR 解析、自动回填入库及持续循环作业流水线的工程架构与运行指引。

---

## 1. 核心架构设计（两阶段异步解耦）

传统爬虫将“网络下载”与“本地 CPU 密集的 OCR 文字识别”同步混杂，容易因单题耗时过长降低吞吐量，且高频调用极易触发服务端风控。本系统采用**网络 I/O 与本地多核计算完全解耦的两阶段架构**：

```text
┌─────────────────────────┐
│ 待抓取试题队列 (3,600题) │
└────────────┬────────────┘
             │
      [第一阶段: 高速网络拉取]
             ▼
┌─────────────────────────┐
│ fetch_answer_images.py  │ ◄── 携带 VIP Token，调用 check_ques_parse
└────────────┬────────────┘     拟人节拍 (1.8~2.6s)，异常探针熔断
             │
             ▼
┌─────────────────────────┐
│  data/answer_images/    │ 高清答案解析原图落盘 (作为一手证据链)
└────────────┬────────────┘
             │
      [第二阶段: 本地多核并行计算]
             ▼
┌─────────────────────────┐
│  batch_ocr_answers.py   │ ◄── 6 线程并行离线 OCR (零网络请求/零风控风险)
└────────────┬────────────┘     双层正则消歧提取标准答案与名师解析长文本
             │
             ▼
┌─────────────────────────┐
│ apply_crawled_answers.py│ ◄── 原子级回填至 questions.jsonl
└────────────┬────────────┘
             │
      [第三阶段: 自动化质检与Git同步]
             ▼
┌─────────────────────────┐
│ validate & report CLI   │ ◄── 100% 结构校验，刷新 review.csv & summary.json
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│   Git Commit & Push     │ ◄── 自动上云备份，永不丢失进度
└─────────────────────────┘
```

## 2. 核心脚本职责清单

| 脚本文件 | 核心职责 | 关键技术实现 |
|---|---|---|
| `scripts/fetch_answer_images.py` | 答案原图高速抓取器 | 携带主站 Cookie 获取动态解密 Key，拉取 884px 高清 PNG；加装 `<10KB` 频控占位图自动识别熔断。 |
| `scripts/batch_ocr_answers.py` | 本地多核并行 OCR 引擎 | 调动 CPU 6 线程离线处理；集成 10 组历史学科答案提取正则与双栏断句规整。 |
| `scripts/apply_crawled_answers.py` | 数据回填与证据链注入 | 将 OCR 缓存原子写入 `questions.jsonl`，规范标记 `single_source` 与 `reliable: true`。 |
| `scripts/run_loop_pipeline.py` | 全自动自愈循环流水线 | 串联“抓取 -> OCR -> 回填 -> 校验 -> Git提交”闭环，内置智能看门狗静默冷却机制。 |
| `scripts/login_sso.js` & `run_login.py` | 可视化扫码与凭证同步 | 唤起独立浏览器窗口支持微信扫码登录，自动同步 `.xkw.com` 与 `.zujuan.xkw.com` 双域令牌。 |

## 3. 账号安全、反爬与风控防护机制

1. **凭证脱敏与数据合规**：
   - 严禁将用户 Cookie、Token 或密码明文提交至 GitHub 仓库；
   - 本地凭证（`data/xkw_cookies.json`）与原图目录（`data/answer_images/`）均在 `.gitignore` 中严格排除。
2. **拟人节拍与呼吸停顿**：
   - 单题下载间隔严格维持在 `1.8 ~ 2.6 秒` 的随机拟人节拍；
   - 每抓取 30 题自动执行 `8 ~ 12 秒` 的模拟翻卷呼吸停顿。
3. **底层探针与自愈看门狗**：
   - 一旦图片服务器返回“访问过于频繁”占位小图（2KB~4KB），流水线立即主动触发安全熔断，退出当前批次；
   - `run_loop_pipeline.py` 自动转入 3~4 分钟的轻量静默守候模式，待服务端滑动窗口放行后自动唤醒开跑。

## 4. 可复现执行命令

```bash
# 1. 刷新登录凭证（如会话过期时弹出扫码窗口）
python scripts/run_login.py

# 2. 运行单批次全自动流水线（例如抓取 100 题）
python scripts/run_auto_pipeline.py 100

# 3. 启动后台全自动自愈循环流水线（跑完剩余全部题目）
python scripts/run_loop_pipeline.py 100
```
